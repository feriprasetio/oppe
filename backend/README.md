# Portal privat OPPE (V6, opsi B)
Status: source implementation for a separately hosted private service, not a deployed production backend or certified TTE. GitHub Pages remains static. No Excel signature asset or real personnel data is committed.

## Install on an authorized RSUD server
- Node.js 22; reverse proxy with valid HTTPS. The process binds 127.0.0.1:8080. Do not expose it directly.
- Run `npm install --prefix backend --omit=dev --ignore-scripts`.
- Copy backend/config.example.json to a private path outside the repository. Replace all fictional entries with verified accounts and staff mappings. Generate individual password hashes using `node backend/hash-password.mjs` with password supplied via stdin (use a protected interactive shell/input). Never commit the private config, password, signature, or document. Use chmod 600 for config and chmod 700 for the data directory.
- Set OPPE_CONFIG=/private/oppe/config.json, OPPE_DATA_DIR=/private/oppe/records, OPPE_ORIGIN=https://your-authorized-host, PORT=8080. Run `node backend/server.js` under a dedicated low-privilege service account. Reverse proxy that exact HTTPS origin to loopback. Add institutional authentication/MFA, rate limiting at proxy, backup, monitoring and security review before production.
- The static frontend exports only assessment request JSON; open the configured private portal and submit as administrator. It does not transmit personnel data or credentials to an arbitrary URL automatically. Staff identity, profession, and approval mapping are server-configured and never trusted from the client. For historical changes specify assignments by each YYYY-Q key; otherwise assignment applies to 12 quarters. No future or provisional quarters, incomplete evidence, or invalid performance values may be submitted.
- Each signer must log in individually and view exact review PDF. The signer uploads their own image, with near-white background removed and crop shown locally. Confirm each selected document; at most 20 per action. Approval binds to server PDF SHA-256, account and current timestamp. When all assigned accounts approve, the server overlays only the approved images and records PDF hash. No replay of image assets from the Excel, no manufactured historic approval date, and no BSrE/PSrE claim. The final PDF is labeled internal archive, not certified TTE.
- The backend retains image only until all required approvals, then removes image from metadata. The finalized PDF retains visible appearance. Record storage is private but not encrypted at application layer; use encrypted filesystem/backups and institution retention policy. Revisions are separate submissions, do not modify finalized bytes. This starter uses a single process and file storage; do not run multiple instances until transactional storage/locking is implemented. No production certification or PKI validation; perform security and browser UAT before use.

## Aset tanda tangan pribadi (V7.1)
Set `OPPE_ASSET_KEY` to a randomly generated 32-byte hex encryption key, stored as a server secret, not in Git. Each authenticated reviewer/committee account may save, load, replace or delete only its own image. Saving/deletion requires the account password and explicit ownership confirmation. Asset files are AES-256-GCM encrypted and bound to account ID. Keep the key backed up securely; loss makes assets unreadable. Approval still requires explicit document selection, the reviewed PDF hash, assigned authority and confirmation; asset registration alone is not approval. No import of other people's signature images, no bulk admin enrollment. Removing an asset does not revoke earlier approvals or change signed PDFs. Use encrypted storage for in-flight approval records and final PDFs. Deployment of this backend is separate from Pages.
